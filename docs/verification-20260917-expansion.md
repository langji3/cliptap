- 默认 28 项测试通过；包含触发词格式、前缀冲突、旧 JSON、DPAPI 加密往返、单行限制、超时与重置、注入按键数量及部分失败释放键、编辑器保存/错误/清空。
- 专用跨进程 WPF 输入测试通过，总计 29 项。实际安装原生钩子，输入标记测试按键：替换中文/emoji、保留 `seed:` 前文、暂停、光标移动、退格、同窗口输入框切换、快速暂停再恢复、下划线触发词、内容更新及删除配置。
- 测试前后 Windows 剪贴板序列号相同。测试不读取剪贴板内容、不向用户库写入示例片段；生产忽略测试标记及其他外部注入。
- 编辑器渲染检查：380×560 窗口内触发词、内容、敏感/置顶和保存按钮可访问。构建无警告/错误。

## 独立审查与处理

审查代理只读检查服务、匹配器、保存及测试。已修复退出时 Dispatcher 通知异常可能从钩子逸出的问题。部分发送失败保持暂停并提示，补发必要的 key-up 防止卡键；不接受自动重试/回滚建议，因为无法核实此时光标和已插入内容。区分大小写、失败需托盘恢复属于本次明确规则。审查所提起始符号丢失不成立，Feed 会优先将 `!` 作为新前缀。

自检另修复跨进程 IMM 查询方式、输入法布局切换重置、快速暂停切换重置，以及中间下划线所需 Shift 处理；末尾要求字母/数字以避免按住 Shift 时执行退格。

## 待实际应用复核

已证明专用 WPF 输入窗口的完整链路，不等同所有浏览器、终端、远程桌面或密码框均兼容。未自动切换用户中文输入法测试其组词行为；状态不可确认时保守跳过。系统安全桌面、管理员窗口与控件对输入的拦截仍受 Windows 限制。非零但部分 SendInput 的原生失败无法稳定制造，释放键策略已作确定性测试。

## 英文模式失效修复

- 用户反馈 Codex 输入框中的 `!253pass` 未替换。只读查询目标窗口的输入法元数据得到布局 `0x08040804`、open=1、conversion=0；旧实现仅接受 open=0，误拦了已开启输入法的英文模式。查询未读取片段值或输入框文本。
- 输入法开启时追加查询转换模式，允许半角字母数字模式及 Roman/软键盘/不转换标志，继续拒绝中文、全角、符号、字符编码、未知模式和查询失败。参考 [Microsoft IME 转换模式](https://learn.microsoft.com/en-us/windows/win32/intl/ime-conversion-mode-values)。
- Release 构建无警告/错误，默认 29 项通过；跨进程测试共 30 项通过。新增敏感数字触发词和模式判断回归，并在专用测试窗口确认 open=1、conversion=0 后输入 `!253pass`，验证替换结果、前文保留和剪贴板序列号不变。
- 测试曾因未获取前台焦点安全停止；设置 WPF 英文偏好后仍返回符号模式 1024 的一次运行也被正确拒绝，随后将专用窗口设为半角英文模式并通过。未在真实 Codex 输入框填入敏感内容，最终真实输入体验由用户复试。
