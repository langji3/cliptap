# ClipTap 0.1 首版验证与交接

## 已实现

- 托盘、单实例、全局快捷键、Windows 原生历史读取与变化订阅；后台启动不创建 WPF 浮窗或渲染表面，首次唤起才创建。
- 双 Tab，左右切换、上下选择、回车/单击插入、Esc/失焦收起。
- 片段创建、编辑、删除、置顶，DPAPI 加密保存与敏感片段遮蔽。
- 浅色、深色、跟随系统；蓝、绿、紫主题色；预览、取消恢复、保存与启动恢复。
- 原生矢量图形、多尺寸 ICO、随主题变化的托盘图标。
- 可选开机启动、Windows 剪贴板设置入口与系统历史清空确认。
- 构建、测试、便携与依赖运行时两种打包脚本、GitHub Windows CI、MIT 许可证。

## 验证结果

环境：Windows x64，.NET SDK 10.0.401，运行时 10.0.12。以下结果对应与本记录一起交付的源码。

`powershell -ExecutionPolicy Bypass -File scripts/build.ps1`：Release 构建通过，0 警告、0 错误，23 项默认测试通过。新增卡片操作事件验证，包含鼠标点击图片恢复、按钮不触发粘贴、Esc 收起操作、删除/清空取消与失败。Tab 切换未改；入场动效代码为 160ms CubicEase 缓出，尊重系统动画开关，测试宿主关闭动画以保证静态截图稳定，实际动效手感需用户确认。

卡片增量独立只读审查已完成；审查提出图片空文本可能阻止粘贴，经源码复核排除（图片值为空字符串，判断仅拦截 null），并补充鼠标事件回归通过。没有改变图片恢复原始记录的路径。

图片验证使用合成 PNG，实际调用 Windows 图片解码器，检查宽图、细长图、单像素图、透明度及 160×96 上限；WPF 图文混排和无缩略图占位均生成截图检查。以假系统源验证恢复所选图片 ID、恢复失败停留列表以及系统删除后拒绝恢复，不写入真实剪贴板。异步 UI 测试显式阻止生产启动逻辑，避免消息循环触发托盘或读取用户库。真实图片恢复到剪贴板及跨应用图片粘贴尚待交互桌面验证。

图片增量独立审查已派发但未按时返回结论，已停止；主代理完成资源释放、失败占位、原记录恢复、未落盘及原有敏感文本流程的自检。未将未完成的独立审查记为通过。

测试包括：原生历史快照替换与删除同步、禁用/拒绝访问/失败状态、失焦期间变化使缓存失效、旧异步结果不能恢复已删记录、系统清空成功/失败及取消、旧本地库兼容和敏感值过滤；另覆盖片段更新、DPAPI、Win32、WPF 键盘/页内导航、敏感遮蔽、主题预览/持久化与六种配色。

图片增量完成后追加 `--system-history` 的只读原生探测，共 23 项通过。本机 `GetHistoryItemsAsync` 返回成功，读取到 3 条文本、2 条图片；只记录状态及计数，未输出真实剪贴板内容。未使用写入样本或清空操作去改变用户的系统历史，Win+V 删除/固定项同步仍需用户在交互桌面补验。系统快照只存内存，未写入本地加密库。

本次独立只读审查未发现确定的同步回归，指出退出期间事件投递的潜在竞态；已为 Dispatcher 关闭增加防护。更新了 Windows 目标框架及运行脚本，使用 SDK 提供的 WinRT 引用。

对生成的主面板、编辑器和设置截图进行了视觉检查，修复了深色列表文字对比度和编辑器高度问题。仓库 README 截图为测试数据，不来自用户剪贴板。

真实后台启动进程未异常退出。此机器启动约 3 秒后的一个采样：工作集约 62 MB，私有内存约 14 MB（未唤起面板）。这是本机采样，不是对所有机器和使用场景的资源承诺；首次打开窗口、历史增多时会增加。

后续调整：默认浅色，快捷键改为 Alt+空格；本机注册成功。已保存的深色/跟随系统选择继续保留。移除标题短描述，并让顶部空白区域可命中拖动事件；设置按钮排除在拖动区域之外。19 项测试复测通过，包含顶部空白区域的实际 WPF 命中检查。

## 尚未通过的交互验证

单面板改版：设置与片段编辑改为 UserControl 页内导航，删除、清空和敏感粘贴改为页内确认；移除常驻说明、空列表文案和按键指南，仅保留短唤醒提示。设置按钮改用矢量滑杆图标，滚动条适配明暗主题。

新增验证覆盖：窗口数量不增加、编辑时方向键和 Enter 不触发列表粘贴、隐藏再打开保留草稿、保存返回原 Tab、删除与清空取消/确认、存储失败保留草稿且不污染已提交数据。截图使用测试数据。独立只读审查发现子页面确认状态会跨隐藏保留，已修复为重新唤起时取消确认、保留草稿，并加入回归检查。

`scripts/build.ps1 -Integration` 的跨进程粘贴测试未通过：测试运行环境无法将专用输入窗口置于前台，目标核验拒绝后续输入。未向错误窗口发送粘贴，也没有把此结果标为成功。

需要在真实交互桌面补验：记事本、浏览器、终端中的唤起/粘贴；中文输入法；管理员窗口失败提示；不同 DPI 多屏定位。自动化对键盘事件和窗口内状态的验证不能替代这些测试。

## 审查与修复

执行了三轮独立只读审查（数据与敏感值、窗口交互、主题与边界增量）。已修复：

1. 启动时格式损坏/版本不受支持的异常需纳入友好提示，不覆盖原文件。
2. 加载时过滤的敏感历史需安排写回，不能只修改内存。
3. 敏感剪贴板清除拒绝未知/零序列号；持有剪贴板锁核验后清除，避免清除后续复制。
4. 设置先保存独立候选状态，成功后替换；失败不提前裁剪历史或改变记录开关，开机启动尝试回滚。

之后追加的主题色、图标与后台延迟创建经针对性测试和主代理复核。没有将测试数据写入用户的应用库。
